# Release notes — v2.1.1

**Compare range:** https://github.com/Swamp-Ig/pizone/compare/v2.1.0...v2.1.1

## Since v2.1.0

### V2 commands retry while the bridge is busy

- Some V2-only bridges reject commands with `{ERROR}` for a few seconds, seemingly while applying an earlier write ([home-assistant/core#194474](https://github.com/home-assistant/core/issues/194474)). V2 commands now retry every 0.5 s for up to 8 s, instead of once after 0.15 s.
- The sending lock is released between tries, so polls and other commands keep running while one command waits.
- A newer write to the same field (for example a zone's maximum airflow) replaces a write that is waiting to retry. The replaced call returns without sending again, and doesn't update the cache or run its later steps, so the newest value wins.
- A command the bridge keeps rejecting now takes up to 8 s to raise `ControllerCommandError`. The first FreeAir command on a bridge without V2 iSave support also waits out the window before falling back to V1.
- V1 commands are unchanged. No API changes.
