# Release notes — v1.3.0 (cached)

Cached 2026-07-12 when resetting the 1.3.x tag line. These notes describe the
intended **v1.3.0** release (commits since `v1.2.10` through layered connection
state). Tags `v1.3.0`–`v1.3.3` were removed in favour of a beta track starting
at `v1.3.b4`.

**Compare range:** https://github.com/Swamp-Ig/pizone/compare/v1.2.10...v1.3.b4

## Summary

Maintenance and modernization release for the Home Assistant iZone integration.
Since `v1.2.10`, the library has been brought up to current Python packaging
and typing practice, moved its HTTP stack to aiohttp, clarified how connection
and command failures are reported, expanded test coverage, and tightened
behaviour around partial device outages.

## Packaging, dependencies, and development

- **Python 3.14** minimum
- Development and releases migrated to **uv** and **Hatchling** (VCS versioning, `py.typed`)
- **aiohttp** (`>=3.14.1`) replaces the custom HTTP client; request timeout raised to **10 seconds**
- **`ifaddr`** replaces `netifaces` for broadcast discovery
- Stricter **mypy** configuration; typing and style cleanup across the codebase
- CI updated (current GitHub Actions, **PyPI trusted publishing**); hardware tests excluded from default CI runs
- Unit test coverage raised to **~92%** with dedicated power, HTTP, and discovery tests

## Error handling and connection behaviour

- **Cached property reads** no longer raise when disconnected; async I/O methods raise **`ConnectionError`** for transport failures
- **`ControllerCommandError`** for reachable devices that reject a request (`{ERROR}` POST body or HTTP 4xx)
- **Layered connection state:** `bridge_connected` (ASH bridge HTTP) and `connected` (bridge plus valid iZone AC data). Fault `SystemSettings` no longer overwrites cached state; Home Assistant can mark entities unavailable through existing disconnect listeners during partial outages (bridge up, AC subsystem down)
- **`Power.connected`** tracks power monitor I/O separately and does not clear `Controller.connected`
- Optional subsystem I/O (power, V2 probe) uses untracked HTTP helpers so init-time probe failures do not poison controller connection state
- Connection restore and reconnect notification fixes, including deduplication of failed init attempts and a `DiscoveryService` shutdown race

## Protocol and performance

- **Zones 13–14** supported via the zone extender endpoint (`Zones13_14`)
- Controller resources refreshed **concurrently** (`asyncio.gather` with serialized HTTP via `_sending_lock`)
- Runtime **V2** and **iPower** capability detection via non-fatal init probes (overrides or supplements discovery datagram hints)

## Documentation

- Public API and I/O method docstrings document exception behaviour and cached-read semantics
- README and inline docs updated for aiohttp requirements and development workflow

## Other fixes

- Discovery accepts `X` in the AC capability slot (per iZone docs, means subsystem unavailable in that slot — not an invalid bridge)
- Power `status_last_reading` key correction
- `controller_reconnected` KeyError when UID missing from internal disconnect tracking
