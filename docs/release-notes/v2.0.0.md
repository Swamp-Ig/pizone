# Release notes — v2.0.0

**Compare range:** https://github.com/Swamp-Ig/pizone/compare/v1.3.12...v2.0.0

This is a major release. It removes the legacy discovery and listener API
that has been deprecated since v1.3.5, and changes how discovery handles
hosts. If you only use `create_discovery()`, `create_controller()`, the
`discover_*` calls and the `refresh_*` methods, the changes you need to make
are small. See **Upgrading from 1.3.x**.

## Since v1.3.12

### Breaking: legacy API removed

These are gone. Use `create_discovery()` and `DiscoveryService.create_controller()`,
and drive refreshes yourself with `refresh_all()` and related methods.

- `pizone.discovery()` and `pizone.Listener`
- `DiscoveryService.add_listener()`, `remove_listener()`, `fetch_controller()`
  and `fetch_controllers()`
- `Controller.refresh()`, `Controller.from_discovery()`, and the
  `REFRESH_INTERVAL` and `UPDATE_REFRESH_DELAY` constants
- The library's own background poll, scan and reconnect loops

### Breaking: discovery verifies hosts over HTTP

- `on_endpoint_discovered` fires only after the bridge answers an HTTP probe
  with the expected UID. A UDP reply on its own no longer produces a
  notification. Replies that fail the check are not notified, but each call
  reports why (see **Breaking: why a bridge wasn't found**)
- A new address reported over UDP is also checked before it is used. A known
  endpoint keeps its old address, and a running controller keeps its address
  without firing `on_address_changed`, until the new address answers
- `discover_by_host()` no longer raises `ControllerAlreadyClaimedError`. Any
  address that answers over HTTP is recorded like a verified UDP reply:
  - a running controller with that UID is moved to it, and its
    `on_address_changed` fires;
  - a new or moved unclaimed endpoint triggers `on_endpoint_discovered`;
  - a controller that is still being created is left alone.

  This lets a host search or a reconfigure fix a controller whose bridge
  moved while UDP was blocked
- `discover_by_uid()` no longer raises `ControllerAlreadyClaimedError` when a
  create for the same UID starts during its scan. It still raises if the UID
  is already claimed when the call starts

### Breaking: why a bridge wasn't found

- `discover_by_host()` raises `EndpointVerifyError` instead of returning
  `None` when the name doesn't resolve or no address answers with usable
  settings
- `discover_by_uid()` raises `EndpointVerifyError` when the UID replied over
  UDP but its address failed the check. It still returns `None` when the UID
  never replied
- `EndpointVerifyError` is a `ConnectionError`, so catch it before broader
  `OSError` handlers. Its `host`, `failure`, `uid` and `answered_uid`
  attributes describe the failure. The message is plain English, meant for
  logs; show users your own text built from the attributes
- New `VerifyFailure` reasons: `UNRESOLVED`, `NO_REPLY`, `UNREADABLE` and
  `OTHER_UID`
- `discover_all()` now returns `DiscoveredEndpoints`, a list of the verified
  endpoints as before, with an `unverified` attribute. It holds an
  `UnverifiedEndpoint` (endpoint, failure, answered UID and time) for each
  bridge that replied during that call but failed the check
- `create_controller()` raises `EndpointVerifyError`, still a
  `ConnectionError`, when it can't reach the controller, so the reason is
  available there too
- Failures during background discovery are logged at debug level on the
  `pizone.discovery` logger

### Host names

- `discover_by_host()` and `create_controller()` accept a host name as well
  as an IPv4 address. The name is resolved to IPv4 addresses, which are
  probed at the same time, and the first one that answers wins
- The library now tracks only UID to IP. Returned endpoints, controllers and
  `on_address_changed` always use the IP, never the name. If you store a host
  name in your configuration, keep it there rather than overwriting it from
  `on_address_changed`

### Controller creation

- `create_controller()` reserves the UID before its first network call. An
  overlapping create for the same UID now raises
  `ControllerAlreadyClaimedError` straight away instead of creating a second
  controller. A failed create puts back the previously known address for that
  UID, if there was one

### Value validation

- New `InvalidValueError`, exported from `pizone`. Setters raise it before
  sending anything when a value is out of range, off its step, or not
  supported by the system or zone. It subclasses both `ValueError` and
  `AttributeError`, so code that catches `AttributeError` keeps working

### System faults

- Any system setting that reports `error`, plus a negative zone count, is now
  reported as a fault. Only faults in `SysMode`, `RAS` or `NoOfZones` take the
  controller offline (`connected` is `False`). Other faulted fields are
  reported, but the settings are still used
- Behaviour changes: `SysMode` reporting `error` on its own now takes the
  controller offline. `SysFan` reporting `error` on its own no longer does,
  because it can be a fan mode the bridge can't name, and `fan` reads as
  `AUTO` in that case
- Faults are logged once at `WARNING` level when the faulted fields appear or
  change, then at `DEBUG` while they persist, and once at `INFO` when they
  clear. Previously a warning was logged on every poll
- `Controller.dump_state()` has a new `last_fault` entry: the time, the
  faulted fields, whether the controller went offline, and the settings the
  bridge sent. It is kept after recovery, so intermittent faults still show
  in diagnostics. It is `None` until a fault is seen

### Fixes

- A V2 `SystemV2` reply that passes the usefulness check but can't be
  converted now falls back to the V1 probe instead of raising

### Diagnostics

- `DiscoveryService.dump_state()` gains `claiming` and `seen` lists alongside
  `claimed` and `known`

### Maintenance

- Ruff 0.17.3 and mypy 2.4.1, matching Home Assistant
- The V1 probe script is linted against Python 3.10, so reporters can still
  run it on older Pythons
- New hardware tests for host handling and broader controller round trips.
  Run them with `uv run pytest -m hardware -o addopts=`

## Upgrading from 1.3.x

1. Replace any use of `discovery()`, `Listener` or `fetch_controller()` with
   `create_discovery()` and `create_controller()`, and call `refresh_all()`
   on your own schedule.
2. Remove handling of `ControllerAlreadyClaimedError` around
   `discover_by_host()`. It is no longer raised there.
3. `discover_by_host()` no longer returns `None` on failure. Catch
   `EndpointVerifyError` from it, and from `discover_by_uid()`, before any
   `OSError` or `ConnectionError` handler, and use its `failure` to tell the
   user why.
4. If you store a host name, don't overwrite it from `on_address_changed`.
   The callback always reports an IP.
5. Optionally catch `InvalidValueError` from setters to report invalid input
   separately from device errors.
