# Release notes — v2.0.1

**Compare range:** https://github.com/Swamp-Ig/pizone/compare/v2.0.0...v2.0.1

## Since v2.0.0

### Name re-resolved after a connection loss

- A controller created from a name with `create_controller(uid, "bridge.lan")` now remembers the name. When an HTTP refresh fails, the name is resolved again in the background, alongside the existing UDP scan.
- If the controller's UID answers at a new address, the controller is repointed and `on_address_changed` fires, the same as for a move found over UDP. This finds a bridge that changed address where UDP discovery can't reach it, such as on another VLAN.
- The check is cooled down per controller. It's skipped when the name still resolves to the current address, or when a UDP verify of that address is already in progress. Failures are logged at debug level only.
- Controllers created from an IP address are unchanged. No API changes.

### Typing

- `DiscoveryService.discover_by_host()` is now annotated as always returning a `ControllerEndpoint`. It has raised `EndpointVerifyError` instead of returning `None` since v2.0.0. Callers can drop their `None` handling.
- `PowerGroup.group_number` returns the number the group was built from, instead of falling back to `-1`, which would also have reported a group 0 as `-1`. `PowerGroup` now takes the group number as a constructor argument; it's built only by `Power`.
